# AI質問機能 要件定義書 (`02_requirements.md`)

## 1. 概要

本ドキュメントは、要望書（`01_request.md`）に基づき、既存の Express / TypeScript 製 Web アプリケーションに「AI質問機能」を追加するための機能要件・非機能要件・画面仕様・制約事項を定義する。

---

## 2. システム構成・採用技術

* **バックエンド**: Express / TypeScript（既存構成を踏襲）


* **ビューテンプレート**: EJS（既存構成 `views/` を踏襲）


* **利用LLM / SDK**: Gemini AI（`@google/genai`）


* **環境変数管理**: `dotenv` を用いて `AI_API_KEY` を読み込む



---

## 3. 機能要件

### 3.1. 画面・UI要件

1. **AI質問画面の提供**
* 独立画面として `/ai`（`views/ai/index.ejs`）を提供する（必要に応じてTOP・TODO画面から遷移リンクを設置可能とする）。


* 画面構成要素:
* 質問入力フォーム（テキストエリア）
* 送信ボタン（送信中は二重送信防止のため非活性化する）
* ローディング表示（AI応答待機中のインジケーター）
* AI回答表示エリア（改行・段落が見やすく表示される領域）
* エラーメッセージ表示エリア




2. **非同期通信による応答表示**
* `public/ai/ai.js` から `fetch` API 等を用いてバックエンドの質問APIへ非同期リクエストを送信し、ページリロードなしで回答を描画する。





### 3.2. 入力バリデーション要件

サーバー側（`aiController.ts`）およびフロントエンド側（`ai.js`）の双方で以下の入力チェックを行う。

| 項目 | 制約条件 | エラー時の挙動 |
| --- | --- | --- |
| **必須チェック** | 空文字および空白文字のみの送信を禁止する

 | HTTP 400 を返却し、「質問を入力してください」等のメッセージを表示

 |
| **型チェック** | 文字列（`string`）であること | HTTP 400 を返却し、不正なリクエストとして処理 |
| **文字数上限** | 1文字以上 〜 2,000文字以内（仮設定） | HTTP 400 を返却し、「質問は2,000文字以内で入力してください」を表示

 |

### 3.3. AI応答処理要件

1. **Gemini API 連携（`aiService.ts`）**
* 環境変数 `AI_API_KEY` を用いて Gemini SDK（`@google/genai`）を初期化する。


* 使用モデルは、高速応答かつコスト効率に優れた標準モデル（例: `gemini-2.5-flash`）を採用する。
* 質問テキストをプロンプトとして渡し、生成されたテキスト回答を返却する。




2. **ステートレスな単発Q&A**
* 初期リリースでは会話履歴のDB保存やマルチターン対話は行わず、1回の質問に対して1回の回答を返すシンプルな構成とする。



### 3.4. エラーハンドリング要件

1. **想定エラーと対応方針**
* **入力バリデーションエラー**: HTTP `400 Bad Request` と具体的なエラーメッセージをJSON形式で返却する。


* **APIキー未設定・設定不備**: サーバー起動時または呼び出し時に検知し、内部ログに詳細を出力した上で、クライアントには HTTP `500 Internal Server Error`（一般的なサーバーエラーメッセージ）を返却する。


* **外部AI API通信エラー・タイムアウト・レート制限**: 例外を適切にキャッチし、サーバーをクラッシュさせず、ユーザーに「現在AIからの回答を取得できません。しばらくしてから再度お試しください」といったフレンドリーなメッセージを返却する。




2. **グローバルエラーハンドラー連携**
* コントローラー内で発生した予期せぬ例外は `next(error)` によって既存の Express グローバルエラーハンドラーへ委譲する。





---

## 4. 非機能要件

1. **アーキテクチャ・ディレクトリ構成の遵守**
* 既存の `src/apps/todo/` と同様に、責務を明確に分離する。


* `src/apps/ai/aiRouter.ts`: ルーティング定義


* `src/apps/ai/aiController.ts`: リクエスト検証・レスポンス整形・例外の `next` 連携


* `src/apps/ai/aiService.ts`: Gemini API 呼び出しロジック






2. **セキュリティ**
* APIキー（`AI_API_KEY`）をソースコードやフロントエンドのJSにハードコードしない。


* AIの回答を画面に描画する際は、XSS（クロスサイトスクリプティング）を防ぐため `textContent` 等を用いて安全にエスケープ処理を行う。


3. **既存機能への非干渉**
* 既存のTODO機能、ルーティング、DB接続、404ハンドリング、エラーハンドリングの処理を変更・破壊しない。





---

## 5. 確定・確認事項（設計フェーズへ進む前のチェック）

以下の点について調整が必要であればお知らせください。特に問題なければ、この内容で確定として次の **設計フェーズ（`03_design.md`）** へ進みます。

1. **画面の配置**: `/ai` の独立ページのみで進めてよいか（TODO一覧画面にも簡易フォームを置くか）。


2. **最大文字数**: 上限 `2,000文字` で問題ないか。


3. **Gemini モデル**: `gemini-2.5-flash` で進めてよいか。
